# ARUUN Reconciliation & Review Protocol

## Purpose

This layer preserves the history of worldbuilding decisions while keeping review material separate from canon and from the tools used to generate the world.

## Classification

- **PRESERVED** — information remains materially present in the newer version.
- **ADDED** — information appears in the newer version without a matching prior fact.
- **MODIFIED** — an established fact remains recognizable but one or more values/details changed.
- **POTENTIAL CANON LOSS** — an established fact from the prior version has no sufficiently similar surviving statement.

## Review rule

The engine never decides canon. Findings are review candidates only. A creator must decide whether a change is intentional, accidental, obsolete, or unresolved.

## Version overlay

For each meaningful historical comparison, review should present:

1. previous version;
2. current version;
3. preserved facts;
4. added facts;
5. modified facts, including changed numeric values;
6. potential information loss;
7. creator decision and resolution.

## Resolution states

- **ACCEPT_CURRENT** — current version becomes the authoritative expression.
- **RESTORE_PRIOR** — information from the prior version must be restored.
- **MERGE** — information from multiple versions must be combined.
- **ARCHIVE_PRIOR** — prior version remains historically available but is not active canon.
- **UNRESOLVED** — requires later creator review.

## Canon rule

Only reviewed decisions may alter the canonical interpretation. Archived material remains available for provenance and future review but is excluded from normal active-canon analysis.

## Folder rule

Document lineage is primarily folder-dependent. A document should be compared against its own path history first. Similar documents elsewhere may be candidates for duplicate/relocation review, but similarity alone does not establish lineage.
