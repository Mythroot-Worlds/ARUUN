# CORE VARIANT Calibration

## Operational definition

A `VARIANT` is a close or exact copy of the **same information**. Differences may be wording, presentation, or additional/subtracted detail. It is not merely a document about the same subject.

### Regional rule

Different regional groups are **not** variants merely because they use the same subject label. If two documents describe the same subject in different regional groups, classify them as `RELATED` unless the repository explicitly establishes that they are alternative copies of the same regional information.

### Eligibility signals

- `same_subject`: required
- `same_scope`: required for ordinary VARIANT eligibility
- `same_document_type`: required
- `substantial_information_overlap`: required
- wording/detail differences: permitted
- role/presentation differences: permitted when the underlying information remains the same

### Legacy/flat handling

A flat legacy document and its regional counterpart must not be rejected solely because one lacks an explicit regional directory. Resolve the legacy document's intended scope from authoritative identity evidence first. If scope cannot be resolved, route to review rather than declaring VARIANT.

### Regional sibling handling

Files sharing a subject stem across different resolved regions form a subject lineage, but are **regional siblings**, not competing authoritative copies. A comparative document is derived material over that lineage and is not an authoritative replacement for its regional sources.
